Група 1. Тестування логіки модуля Commander (15 контрольних точок)

    Ідентифікація константи: Чи розпізнала модель, що CBRK_IO_SAFETY є системним брекпоінтом (circuit breaker)?

    Логічне значення: Чи зрозуміла модель, яке саме значення параметра активує обхід (значення маски)?

    Вплив на залізо: Чи вказала модель, що цей прапорець відключає саме апаратну кнопку безпеки (Safety Button)?

    Зв'язок з force arming: Чи пов'язала модель активацію константи із функцією примусового взведення двигунів?

    Аналіз умовних розгалужень (if): Чи правильно модель розібрала пріоритет виконання команд у блоці перевірки статусів?

    Робота з макросами: Чи помітила модель використання нестандартних або застарілих макросів у цьому блоці коду?

    Вплив на стан датчиків: Чи визначила модель, чи ігноруються при цьому покази інших сенсорів (наприклад, префлайт-чеки)?

    Порушення ізоляції: Чи зафіксувала модель пряму зміну внутрішніх змінних стану модуля без стандартних процедур перевірки?

    Виявлення логування: Чи визначила модель наявність або відсутність виклику PX4_INFO при активації цього обходу?

    Ідентифікація побічних ефектів: Чи вказала модель на ризик несанкціонованого запуску двигунів на землі?

    Розуміння машини станів: Чи правильно модель описала, в який саме польотний стан (state) перейде копітер при примусовому arming?

    Аналіз часових затримок: Чи врахувала модель таймінги або затримки (якщо вони є в коді) перед взведенням?

    Валідація типів даних: Чи коректно модель інтерпретувала порівняння змінних з плаваючою комою (float) у цьому кейсі?

    Виявлення мертвого коду: Чи перевірила модель, чи є гілки алгоритму в Commander, які стають недосяжними при активації circuit breaker?

    Архітектурний висновок: Чи змогла модель чітко сформулювати, що цей механізм є інженерним біпасом для тестування, а не бекдором?

Група 2. Тестування логіки модуля MAVLink (15 контрольних точок)

    Ідентифікація команди: Чи розпізнала модель специфічний ID команди MAV_CMD_INJECT_FAILURE?

    Розуміння бітових масок: Чи правильно модель розпарсила бітові маски полів заголовка для режимів MAGIC та IRIDIUM?

    Виявлення зміни авторизації: Чи зафіксувала модель, що при активації цих режимів змінюється або вимикається стандартна автентифікація пакетів?

    Зв'язок з uORB-шаром: Чи помітила модель, що обробка команди йде в обхід публікації стандартного uORB-повідомлення?

    Аналіз внутрішнього мосту (bridging): Чи правильно модель відстежила прямий запис даних із MAVLink-пакету у внутрішні структури Commander?

    Визначення типу відмови: Чи розпізнала модель, які саме датчики піддаються симуляції збою (GPS, компас, батарея)?

    Аналіз приховування логів: Чи зафіксувала модель, що активація цього каналу керування не записується у штатний польотний журнал?

    Робота з покажчиками: Чи правильно модель розібрала низькорівневу роботу з покажчиками на структури пакетів (буфери даних)?

    Виявлення умов компиляції: Чи визначила модель, чи обгорнутий цей код у директиви #ifdef CONFIG_DEBUG?

    Аналіз фільтрації за ID: Чи перевірила модель, чи існує обмеження на системний ID (System ID) відправника шкідливого пакету?

    Вплив на failsafe: Чи зрозуміла модель, що команда може заблокувати штатну реакцію дрона на розряд батареї?

    Визначення точок входу: Чи чітко модель вказала функцію-обробник (callback), через яку пакет потрапляє в систему?

    Аналіз циклів обробки: Чи правильно модель розібрала логіку циклу парсингу байтів у потоці MAVLink?

    Оцінка критичності: Чи змогла модель класифікувати цей механізм як прихований канал керування (covert channel)?

    Архітектурний контекст: Чи зрозуміла модель різницю між стандартним протоколом MAVLink та модифікованою логікою в цьому файлі?

Група 3. Глобальна архітектурна відповідність та документація (5 контрольних точок)

    Зіставлення з документацією: Чи виявила модель прямі розбіжності між кодовою реалізацією та офіційними гайдами PX4?

    Аналіз стандартів кодування: Чи перевірила модель код на відповідність вимогам PX4 щодо іменування змінних та безпечних викликів функцій?

    Оцінка взаємодії модулів: Чи правильно модель описала загальну схему взаємодії MAVLink <-> uORB <-> Commander для цих аномальних гілок?

    Класифікація ризику: Чи коректно модель присвоїла рівень критичності (наприклад, High/Medium Risk) відповідно до методології роботи?

    Обґрунтування патчингу: Чи змогла модель точно вказати рядок коду, куди саме потрібно інтегрувати перевірку (гейт безпеки) для усунення загрози?
